Dưới đây là bản **master prompt để giao cho coding agent**. Mình viết theo hướng:

* agent có thể bắt tay dựng project ngay
* bám đúng mục tiêu “project khung điều phối”
* không sa đà build full feature quá sớm
* có thứ tự làm việc, tiêu chí hoàn thành, file cần tạo, quy tắc tích hợp

Bạn có thể copy nguyên khối này để giao cho agent.

# Master Prompt cho Coding Agent

```text
Bạn là coding agent chịu trách nhiệm dựng bộ khung cho project "AI Team Sharing Assistant".

## 1. Bối cảnh
Mục tiêu của project này không phải build full product ngay từ đầu.
Mục tiêu hiện tại là dựng một "master skeleton project" làm bộ xương liên kết toàn bộ hệ thống, để các thành viên khác trong team có thể implement từng module riêng và tích hợp vào sau.

Project này phải cho phép:
- định nghĩa rõ workflow tổng thể
- định nghĩa contract input/output cho từng module
- chạy được end-to-end bằng mock data
- thay dần mock bằng implementation thật mà không phải sửa kiến trúc chính

## 2. Mục tiêu chính
Hãy implement một project skeleton có khả năng điều phối flow sau:

Load team profiles
-> Analyze knowledge gaps
-> Generate topics
-> Rank topics
-> Export topics for voting
-> Simulate vote result
-> Select winning topic
-> Generate topic brief
-> Generate slide outline
-> Create session draft
-> Simulate feedback
-> Evaluate session
-> Save all artifacts

Project phải chạy được flow trên bằng mock implementation.

## 3. Phạm vi công việc
Bạn chỉ dựng bộ khung và workflow orchestration.
Không cần build đầy đủ AI thật hoặc integration thật ngay.

### Những gì phải có
- monorepo hoặc modular repo structure rõ ràng
- shared schemas
- module interfaces
- mock providers cho từng module
- workflow orchestrator
- artifact output storage
- config system
- contract tests
- sample data
- docs cơ bản để team khác có thể làm tiếp

### Những gì chưa cần làm sâu
- chưa cần LLM thật cho tất cả module
- chưa cần Slack API thật
- chưa cần Google Calendar integration thật
- chưa cần DB production
- chưa cần UI
- chưa cần multi-agent phức tạp

## 4. Yêu cầu công nghệ
Ưu tiên stack đơn giản, dễ maintain, dễ để agent khác tiếp tục.

### Dùng:
- Node.js
- TypeScript
- Zod hoặc JSON Schema để validate schema
- Vitest hoặc Jest để test
- file-based storage trước
- config bằng JSON hoặc YAML

### Không cần:
- kiến trúc microservices phức tạp
- database production ngay từ đầu
- workflow engine ngoài nếu chưa cần
- framework quá nặng nếu không cần thiết

## 9. Provider architecture
Mỗi module phải hỗ trợ ý tưởng provider-based architecture.

Tức là mỗi module có thể có:
- mock provider
- rule-based provider
- ai-api provider
- cli provider
- agent provider

Hiện tại chỉ cần implement:
- interface provider
- mock provider
- real provider placeholder

Phải có provider registry hoặc config mechanism để về sau có thể chọn provider theo module mà không sửa orchestrator.

Ví dụ:
- topic-generation = mock
- content = mock
- scheduling = mock
- evaluation = mock

## 10. Orchestrator requirements
Hãy tạo một workflow orchestrator có khả năng:

- truyền state giữa các bước
- log kết quả từng bước
- ghi artifacts ra thư mục outputs
- hỗ trợ chế độ mock end-to-end
- hỗ trợ review checkpoints trong tương lai

### Orchestrator cần có:

## 14. Logging và artifact output
Project phải ghi rõ output của mỗi bước ra data/outputs.

Ví dụ:

Ngoài ra, trong docs/contracts cần có mô tả ngắn contract của từng module.

Chỉ được xem là xong khi:
```

```text
Tiếp tục từ project skeleton hiện tại.

Mục tiêu:
- review lại toàn bộ contract giữa các module
- kiểm tra mock workflow đã đủ ổn chưa
- cải thiện provider registry nếu cần
- bổ sung example input/output cho từng module
- đảm bảo mỗi module có README riêng

2. Không thay đổi schema một cách tùy tiện
3. Ưu tiên cải thiện clarity và maintainability
4. Tạo checklist handoff cho từng module

Kết quả mong muốn:
- project sẵn sàng để chia cho team implement từng phần
- mỗi module có contract rõ ràng
- có hướng dẫn tích hợp đủ để người khác làm độc lập
```

# Checklist để bạn review output của agent

Khi agent trả bài, bạn check lần lượt:

## Kiến trúc

* Có đúng là skeleton project không
* Có overbuild không
* Thư mục có rõ ràng không

## Contract

* Schema có rõ không
* Input/output có nhất quán không
* Module có độc lập không

## Workflow

* Full mock flow có chạy được không
* Có lưu artifact không
* Có log dễ đọc không

## Tính tích hợp

* Có chỗ để cắm implementation thật không
* Có provider registry/config không
* Có README cho team khác tiếp tục không

## Chất lượng kỹ thuật

* Có test không
* Có sample data không
* Có file thừa hoặc logic rối không

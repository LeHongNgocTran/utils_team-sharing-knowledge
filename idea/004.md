Dưới đây là bản **high-level nhưng đủ thực dụng**: mỗi quy trình nhỏ có **mục tiêu, phương pháp thực hiện, công nghệ/công cụ, input, output** để bạn review scope. Mình sẽ ghi theo hướng **MVP trước, mở rộng sau**.

# 1. Team Profiling

## Mục tiêu

Hiểu team đang ở level nào, thiếu gì, muốn phát triển gì để hệ thống không sinh topic ngẫu nhiên.

## Phương pháp thực hiện

* Tạo form thu thập hồ sơ thành viên
* Chuẩn hóa dữ liệu về level, kỹ năng, domain, mục tiêu phát triển
* Biến dữ liệu thô thành “team capability map”
* Có thể update định kỳ theo tháng hoặc theo quý

## Công nghệ / công cụ

**MVP**

* Google Forms để thu thập dữ liệu
* Google Sheets / PostgreSQL để lưu dữ liệu
* Backend Node.js / NestJS hoặc Express để xử lý
* Cron job / n8n để đồng bộ dữ liệu định kỳ

**Nâng cao**

* Slack form / workflow để thu thập ngay trong Slack
* Dashboard nội bộ để edit profile dễ hơn

Google Forms API cho phép tạo, sửa form và lấy response; đồng thời có thể lấy response về để xử lý tiếp. Slack cũng có Workflow Builder và form-based automation để thu thập thông tin ngay trong workspace. n8n phù hợp cho automation giữa các app như Slack, Gmail, Calendar. ([Google for Developers][1])

## Input

* Tên thành viên
* Level
* Kỹ năng cứng
* Kỹ năng mềm
* Domain knowledge
* Mục tiêu phát triển
* Pain point hiện tại
* Chủ đề muốn học

## Output

* Hồ sơ từng thành viên
* Team skill matrix
* Knowledge gaps tổng quan
* Danh sách chủ đề quan tâm ban đầu

# 2. Knowledge Gap Analysis

## Mục tiêu

Từ dữ liệu team, tìm ra khoảng trống kiến thức để sinh topic đúng nhu cầu.

## Phương pháp thực hiện

* Chuẩn hóa các skill thành taxonomy chung
* Gom nhóm theo domain, level, nhu cầu
* Tính chênh lệch giữa “năng lực hiện tại” và “năng lực mong muốn”
* Ưu tiên những khoảng trống xuất hiện ở nhiều người hoặc ảnh hưởng trực tiếp công việc

## Công nghệ / công cụ

**MVP**

* Rule-based scoring bằng code backend
* PostgreSQL để query và tổng hợp
* Python service hoặc Node service để tính score

**Nâng cao**

* Embedding model để gom các nhu cầu gần nghĩa
* Vector DB như Qdrant để lưu embedding của skill/topic/profile notes
* Hybrid search để kết hợp keyword + semantic search

Qdrant hỗ trợ semantic search, filtering và hybrid search; đây là lựa chọn hợp lý nếu sau này bạn muốn tìm gap hoặc topic theo cả ngữ nghĩa lẫn filter cấu trúc. ([qdrant.tech][2])

## Input

* Member profiles
* Skill taxonomy
* Lịch sử topic cũ
* Feedback các buổi trước

## Output

* Danh sách knowledge gaps
* Nhóm nhu cầu ưu tiên
* Tập nhãn chủ đề tiềm năng để sinh topic

# 3. Topic Generation

## Mục tiêu

Sinh ra khoảng 10 topic có căn cứ, không chỉ là danh sách tiêu đề.

## Phương pháp thực hiện

* Dùng prompt template + dữ liệu team
* Sinh topic theo từng nhóm: technical, business, process, soft-skill
* Mỗi topic phải có:

  * title
  * overview
  * background
  * lý do nên học
  * target audience
  * difficulty
  * expected impact

## Công nghệ / công cụ

**MVP**

* LLM API để generate topic card
* Backend service quản lý prompt
* JSON schema để ép output ổn định

**Nâng cao**

* LangGraph để chia workflow thành các node: phân tích team → sinh topic → kiểm tra trùng lặp → chấm điểm
* RAG nhẹ để kéo thêm ngữ cảnh từ lịch sử sharing nội bộ

LangGraph phù hợp cho workflow có thứ tự rõ ràng hoặc workflow dạng graph, có state, persistence và debugging; nó hợp với bài toán pipeline nhiều bước như generate → evaluate → refine. ([LangChain Docs][3])

## Input

* Knowledge gaps
* Team profile summary
* Topic history
* Scope rules
* Prompt template

## Output

* 10 topic cards hoàn chỉnh
* Metadata của từng topic
* Danh sách topic có thể đem đi vote

# 4. Topic Scoring & Prioritization

## Mục tiêu

Không chọn topic chỉ vì “nghe hay”, mà vì phù hợp và đáng đầu tư.

## Phương pháp thực hiện

Tính điểm cho mỗi topic dựa trên:

* Relevance với công việc hiện tại
* Match với level team
* Coverage: số người hưởng lợi
* Novelty: tránh trùng quá nhiều topic cũ
* Strategic value: hỗ trợ hướng phát triển dài hạn
* Historical signal: topic tương tự trước đây hiệu quả ra sao

## Công nghệ / công cụ

**MVP**

* Rule engine bằng code
* PostgreSQL lưu score breakdown
* Simple ranking formula

**Nâng cao**

* Learning-to-rank đơn giản
* Re-ranker model cho semantic matching
* Feature store nhỏ cho topic signals

## Input

* Topic cards
* Vote history
* Feedback history
* Team profile summary

## Output

* Topic score
* Ranked topic list
* Top 10 danh sách đi vote

# 5. Voting & Topic Selection

## Mục tiêu

Cho team chọn topic nhanh, ít ma sát.

## Phương pháp thực hiện

* Gửi 10 topic qua Slack hoặc email
* Mỗi người vote 1–3 topic
* Có ô nhập “đề xuất topic khác”
* Thu cả số vote và lý do ngắn
* Hệ thống chốt 1 topic chính + vài topic dự phòng

## Công nghệ / công cụ

**MVP**

* Slack poll hoặc message với link form
* Google Forms cho vote có cấu trúc
* Gmail/Slack để notify

Slack có thể dùng poll app hoặc quick poll trong message; Google Forms API đọc/ghi response được; Gmail API hỗ trợ tạo draft và gửi mail. ([Slack][4])

## Input

* 10 topic cards
* Danh sách người tham gia
* Voting window
* Optional free-text topic suggestions

## Output

* Topic thắng cuộc
* Topic dự phòng
* Vote analytics
* Danh sách topic tự đề xuất thêm

# 6. Content Preparation

## Mục tiêu

Giảm mạnh công chuẩn bị cho người trình bày.

## Phương pháp thực hiện

* Từ topic thắng cuộc, AI sinh:

  * overview
  * learning objective
  * agenda
  * key points
  * examples
  * speaker notes
  * FAQ
* Presenter chỉ review và chỉnh sửa

## Công nghệ / công cụ

**MVP**

* LLM API
* Template engine cho topic brief
* Google Docs / Markdown / Notion-style document output

**Nâng cao**

* Tự sinh slide outline
* Tự sinh handout 1 trang
* Tự sinh phiên bản ngắn cho email/slack teaser

## Input

* Topic thắng
* Audience level
* Desired duration
* Style guideline
* Historical material nếu có

## Output

* Topic brief
* Agenda
* Notes cho presenter
* Draft nội dung buổi sharing

# 7. Slide Draft Generation

## Mục tiêu

Sinh khung slide đủ tốt để thuyết trình không bắt đầu từ trang trắng.

## Phương pháp thực hiện

* Chuyển agenda thành slide sections
* Mỗi section có:

  * mục tiêu
  * 1–3 ý chính
  * ví dụ
  * takeaway
* Chỉ nên tạo draft, không cố tạo “deck hoàn chỉnh tuyệt đối”

## Công nghệ / công cụ

**MVP**

* JSON slide schema
* Google Slides API hoặc PowerPoint generation
* HTML-to-slide hoặc markdown-to-slide pipeline

**Nâng cao**

* Tự đề xuất visual type cho từng slide
* Tự sinh speaker note và recap slide

## Input

* Topic brief
* Agenda
* Branding guideline
* Timebox buổi sharing

## Output

* Slide outline
* Slide draft
* Speaker note draft

# 8. Session Scheduling & Notification

## Mục tiêu

Biến topic thành buổi sharing thật sự diễn ra.

## Phương pháp thực hiện

* Chọn thời gian từ slot có sẵn
* Tạo calendar event
* Gửi mail/slack
* Nhắc trước buổi
* Gửi tài liệu chuẩn bị trước

## Công nghệ / công cụ

**MVP**

* Google Calendar API
* Gmail API
* Slack API hoặc Slack workflow
* n8n để nối luồng tự động

Google Calendar API hỗ trợ tạo event qua `events.insert`; Gmail API hỗ trợ draft/send email; Slack Web API dùng để tương tác với workspace; n8n có sẵn tích hợp kiểu Slack + Google Calendar. ([Google for Developers][5])

## Input

* Topic đã chọn
* Presenter
* Candidate timeslots
* Participant list
* Room or meeting mode

## Output

* Calendar event
* Email/slack notification
* Reminder schedule
* Session status

# 9. Room Booking / Logistics

## Mục tiêu

Chốt điều kiện tổ chức buổi sharing.

## Phương pháp thực hiện

* Nếu onsite: chọn phòng, sức chứa, thiết bị
* Nếu online: tạo Meet/Zoom link
* Gắn link/phòng vào event

## Công nghệ / công cụ

**MVP**

* Google Calendar event + location/meet link
* Bảng room inventory lưu nội bộ

**Nâng cao**

* Tích hợp room booking system nội bộ
* Tự check conflict phòng

Google Calendar event hỗ trợ các trường start/end và chi tiết event; có thể dùng như điểm trung tâm để gắn location hoặc meeting details. ([Google for Developers][5])

## Input

* Thời gian đã chọn
* Số người tham gia
* Hình thức online/offline
* Ràng buộc phòng

## Output

* Room assignment / meeting link
* Logistics note

# 10. Post-sharing Feedback Collection

## Mục tiêu

Đo giá trị thật của topic sau buổi sharing.

## Phương pháp thực hiện

* Gửi form ngắn ngay sau buổi
* Chỉ hỏi ít nhưng đúng trọng tâm:

  * hữu ích không
  * có áp dụng được không
  * có đúng level không
  * muốn học tiếp không
  * góp ý tự do
* Cố gắng thu cả định lượng và định tính

## Công nghệ / công cụ

**MVP**

* Google Forms
* Slack form/workflow
* Sheets/PostgreSQL để lưu feedback

**Lưu ý**
Google Forms API đang có thay đổi: form tạo qua API sẽ mặc định ở trạng thái unpublished sau mốc 30/6/2026 nếu không xử lý phần publish/control tương ứng, nên nếu đi theo hướng Forms API thì cần tính trước chuyện này. ([Google for Developers][6])

## Input

* Session ID
* Participant list
* Topic metadata

## Output

* Feedback responses
* Ratings
* Open comments
* Continuation demand

# 11. Topic Evaluation

## Mục tiêu

Biến feedback thành quyết định cho vòng sau.

## Phương pháp thực hiện

Tạo evaluation score từ các nhóm:

* Relevance
* Practical Value
* Difficulty Fit
* Clarity
* Continuation Potential

Sau đó phân loại topic:

* Expand
* Repeat with better delivery
* Too basic
* Too advanced
* Wrong timing
* Low value

## Công nghệ / công cụ

**MVP**

* Rule-based scoring
* Dashboard đơn giản
* PostgreSQL lưu evaluation summary

**Nâng cao**

* Topic recommendation engine dùng historical outcomes
* Clustering feedback comments bằng embedding

## Input

* Vote data
* Attendance
* Feedback ratings
* Free-text comments

## Output

* Topic evaluation result
* Decision tag
* Gợi ý next topics
* Tín hiệu cho lần generate sau

# 12. Knowledge Memory

## Mục tiêu

Lưu lại toàn bộ chu kỳ để hệ thống học dần lên.

## Phương pháp thực hiện

Lưu:

* topic generated
* topic selected
* voting result
* materials
* session metadata
* feedback
* evaluation result
* next-topic links

## Công nghệ / công cụ

**MVP**

* PostgreSQL cho structured data
* Object storage / Drive cho slide, docs
* Simple tagging

**Nâng cao**

* Vector DB cho semantic retrieval
* Hybrid search để tìm topic tương tự, history tương tự

Qdrant là lựa chọn phù hợp cho semantic/hybrid retrieval khi bạn muốn truy hồi topic cũ, feedback cũ hoặc material cũ theo nghĩa thay vì chỉ theo keyword. ([qdrant.tech][2])

## Input

* Toàn bộ dữ liệu từ các bước trước

## Output

* Topic history
* Searchable knowledge base
* Signals cho vòng generate mới

# 13. Orchestration Layer

## Mục tiêu

Nối tất cả các bước thành một flow chạy được ngoài đời thật.

## Phương pháp thực hiện

* Dùng workflow orchestration
* Mỗi bước là một job hoặc node
* Có retry, log, manual override
* Cho phép chạy theo schedule hằng tuần

## Công nghệ / công cụ

**MVP**

* n8n cho automation liên app
* Backend service làm business logic
* Cron / queue cho schedule

**Nâng cao**

* LangGraph nếu muốn agent/workflow stateful hơn
* Temporal/BullMQ nếu muốn job orchestration nghiêm túc hơn

n8n mạnh ở app automation; LangGraph mạnh ở workflow/agent có state và nhiều bước xử lý AI. Hai thứ này có thể đi chung: n8n cho integration, LangGraph cho intelligence flow. ([n8n Docs][7])

## Input

* Schedule
* Workflow config
* API credentials
* Business rules

## Output

* End-to-end automation run
* Logs
* Failed step alerts
* Final artifacts

# 17. Bản rút gọn cực nhanh

## Mỗi quy trình nhỏ cần có

* **Input layer**: profile, lịch sử, feedback
* **AI layer**: phân tích gap, generate topic, score topic
* **Selection layer**: vote, chọn topic
* **Preparation layer**: overview, agenda, slide draft
* **Execution layer**: notify, calendar, room
* **Evaluation layer**: feedback, score sau buổi
* **Memory layer**: lưu lại để vòng sau tốt hơn

Được. Đây là cách làm rất hợp lý.

Bạn nên làm một **project khung điều phối** trước, chỉ tập trung vào:

* định nghĩa luồng tổng thể
* chuẩn hóa input/output giữa các module
* dựng nơi để cắm từng thành phần vào
* cho phép chạy end-to-end dù nhiều phần vẫn còn là mock

Như vậy:

* bạn không phải chờ cả team xong mới ghép
* mỗi người làm độc lập theo contract rõ ràng
* agent có thể implement từng phần nhỏ mà không phá toàn hệ thống

Dưới đây là bản kế hoạch theo kiểu để **giao cho agent làm từng bước**.

---

# 1. Mục tiêu của project khung

Xây một **orchestrator project** làm bộ xương cho hệ thống “AI Assistant for Team Sharing”.

Project này chưa cần hoàn thiện toàn bộ AI logic ngay.
Mục tiêu trước là:

1. tạo cấu trúc thư mục và kiến trúc rõ ràng
2. định nghĩa các module chính
3. định nghĩa contract input/output cho từng module
4. cho phép chạy một flow mẫu end-to-end
5. hỗ trợ thay thế mock implementation bằng implementation thật sau này

---

# 2. Nguyên tắc implement

## Nguyên tắc 1

**Orchestrator trước, intelligence sau.**
Tức là dựng hệ thống nối các bước trước, còn AI sâu hay integration thật thì cắm dần.

## Nguyên tắc 2

**Mỗi module phải có interface rõ ràng.**
Agent hoặc thành viên chỉ cần bám interface để implement.

## Nguyên tắc 3

**Mock trước, thật sau.**
Mỗi module đều cần:

* interface
* mock provider
* real provider placeholder

## Nguyên tắc 4

**Tất cả dữ liệu đi qua schema chung.**
Không để mỗi người tự truyền object khác nhau.

## Nguyên tắc 5

**Flow phải chạy được kể cả khi mới xong 20–30%.**
Ví dụ:

* topic generation chưa xong → dùng mock topics
* slide generation chưa xong → xuất markdown outline
* scheduling chưa xong → ghi log event giả

# 3. Phạm vi của project khung

Project khung sẽ chịu trách nhiệm cho các phần:

* quản lý config hệ thống
* chứa schema dùng chung
* định nghĩa workflow
* điều phối các module
* log trạng thái từng bước
* lưu artifacts tạm
* hỗ trợ mock / real mode

Project khung **chưa cần** làm sâu:

* AI scoring quá phức tạp

* slide đẹp hoàn chỉnh

# 4. Các module cần có trong bộ khung

## 4.1. Profile Module

Chịu trách nhiệm:

* nhận dữ liệu thành viên
* validate
* normalize cơ bản
* trả ra team profile summary

## 4.2. Gap Analysis Module

Chịu trách nhiệm:

* đọc team profile
* sinh knowledge gaps
* xuất priority gaps

## 4.3. Topic Generation Module

Chịu trách nhiệm:

* sinh danh sách topic cards từ gap analysis

## 4.4. Topic Ranking Module

Chịu trách nhiệm:

* tính điểm topic
* sắp xếp topic trước khi vote

## 4.5. Voting Module

Chịu trách nhiệm:

* nhận vote data
* tổng hợp
* chọn topic thắng

## 4.6. Content Preparation Module

Chịu trách nhiệm:

* tạo overview
* agenda
* summary
* notes

## 4.7. Slide Draft Module

Chịu trách nhiệm:

* chuyển content thành slide outline

## 4.8. Scheduling Module

Chịu trách nhiệm:

* nhận session info
* tạo event draft
* notify draft

## 4.9. Feedback Module

Chịu trách nhiệm:

* nhận feedback sau buổi
* chuẩn hóa phản hồi

## 4.10. Evaluation Module

Chịu trách nhiệm:

* chấm topic sau buổi
* phân loại outcome
* gợi ý next action

## 4.11. Memory Module

Chịu trách nhiệm:

* lưu topic, vote, session, feedback, evaluation
* hỗ trợ truy xuất lịch sử

## 4.12. Orchestrator Module

Chịu trách nhiệm:

* gọi đúng module đúng thứ tự
* quản lý state flow
* xử lý retry, failure, manual stop

# 5. Luồng end-to-end cần implement trước

Bản đầu tiên chỉ cần chạy được flow này:

```text
Load team profiles
-> Analyze knowledge gaps
-> Generate topics
-> Rank topics
-> Export topics for voting
-> Simulate vote result
-> Select winning topic
-> Generate topic brief
-> Generate slide outline
-> Create session draft
-> Simulate feedback
-> Evaluate session
-> Save all artifacts
```

Đây là bản MVP orchestration.

# 9. Kế hoạch implement theo phase

## Phase 1 — Foundation

Mục tiêu:

* dựng repo
* dựng cấu trúc package
* dựng schemas
* dựng orchestrator cơ bản
* tạo sample data

### Task cho agent

1. khởi tạo monorepo hoặc modular repo
2. tạo folder structure
3. tạo package schemas
4. tạo package core
5. tạo package shared utils
6. tạo sample JSON data cho members, topics, votes, feedback
7. tạo README mô tả kiến trúc
8. tạo docs/contracts cho từng module

### Deliverable

* repo chạy được
* build pass
* docs có sẵn
* sample data dùng được

---

## Phase 2 — Module Contracts

Mục tiêu:

* tất cả module có interface chuẩn
* có mock implementation

### Task cho agent

1. tạo interface cho từng module
2. tạo DTO/type/schema tương ứng
3. tạo mock executor cho từng module
4. viết test schema validation
5. viết test mock output

### Deliverable

* tất cả module đều có execute()
* tất cả output đúng schema
* chưa cần AI thật

---

## Phase 3 — Workflow Orchestrator

Mục tiêu:

* chạy được end-to-end mock workflow

### Task cho agent

1. tạo WorkflowRunner
2. tạo step registry
3. tạo state store trong runtime
4. nối các module theo flow chuẩn
5. log từng bước ra console + file
6. lưu artifact của từng bước vào data/outputs

### Deliverable

* chạy 1 lệnh là flow hoàn thành
* có artifacts output
* có run summary

---

## Phase 4 — Human Review Points

Mục tiêu:

* có thể dừng ở các bước quan trọng để review

### Task cho agent

1. thêm manual approval hooks sau:

   * topic ranking
   * topic selection
   * content generation
   * scheduling draft
   * evaluation result
2. cho phép run ở 2 mode:

   * auto
   * review-required

### Deliverable

* workflow không quá cứng
* dễ review trước khi đi tiếp

---

## Phase 5 — Provider Architecture

Mục tiêu:

* cho phép mỗi module có nhiều cách implement

### Mô hình

Mỗi module có thể có:

* mock provider
* rule-based provider
* ai-api provider
* cli provider
* agent provider

### Task cho agent

1. thiết kế provider registry
2. cho phép config chọn provider theo module
3. thêm config ví dụ:

   * topic-generation = mock
   * content = ai-api
   * scheduling = mock

### Deliverable

* thay provider không cần sửa orchestrator

---

## Phase 6 — Real Integration từng phần

Mục tiêu:

* từng thành viên trong team có thể nhận 1 module và cắm bản thật vào

### Cách chia

* người A làm topic generation
* người B làm content + slide
* người C làm voting + scheduling
* người D làm feedback + evaluation

### Task cho agent

1. chuẩn bị integration guide cho từng module
2. tạo checklist “done criteria”
3. tạo test harness để module mới có thể test độc lập

### Deliverable

* module nào xong có thể cắm vào ngay
* không phụ thuộc người khác

# 12. Ví dụ task giao cho agent

## Task: Implement Topic Generation Module Skeleton

### Mục tiêu

Tạo module skeleton cho Topic Generation.

### Yêu cầu

* tạo interface `ITopicGenerationModule`
* input là `GapAnalysisResult`
* output là `TopicGenerationResult`
* tạo mock provider trả về 10 topic giả
* validate output bằng schema
* viết test cho:

  * valid input
  * empty gaps
  * mock output count = 10

### File cần tạo

* interface
* types/schema
* mock provider
* unit test
* README module

### Không làm

* chưa tích hợp LLM thật
* chưa gọi API ngoài

### Definition of done

* test pass
* mock run được từ orchestrator
* output lưu được vào artifact folder
